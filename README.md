# 拼圖接龍 JigsawCard Solitaire（自製版）

參考 [JigsawCard Solitaire Puzzle](https://apps.apple.com/my/app/jigsawcard-solitaire-puzzle/id6754900673) 做嘅同類型遊戲：一張靚圖切成 N x N 格、打亂晒，你拖曳交換任何兩格位置，將圖砌返晒。用 React + Vite 起，用 Capacitor 包裝就可以上架 App Store / Google Play。

## 玩法設計

- 每關開始，一張主題相已經切成 N x N 格鋪滿成個棋盤，但每格位置係打亂咗嘅（唔係得返一個空格嗰種滑塊拼圖，係全部格都有相）。
- 拖曳任何一格，放落另一格度，兩格會交換位置 —— 可以交換棋盤上任何兩個位置，唔限於相鄰嘅上下左右格。
- 一格拖去咗自己正確嘅位置就會**鎖定**（有綠色框highlight），鎖定咗嘅格唔可以再拖動。全部格都鎖定晒就過關。
- 每次交換令到有新格鎖定，會彈出「Nice! / Great! / Excellent!」鼓勵字樣，連續交換連續鎖定會計combo（例如連續3次會顯示 x3）；一旦有一次交換冇令到任何格鎖定，combo會重置。
- 冇計時器，唔會扣分。右上角有復原（↺）、提示（💡，每關有限次數，會highlight一格應該搬去邊）。
- 12關，分3個難度梯度（4x4 → 5x5 → 6x6，逐關棋盤變大）。過關會解鎖下一關，進度存喺手機本機（localStorage）。

核心引擎（`src/game/engine.js`）用排列（permutation）模型：每格嘅id就係佢正確嘅位置index，`cells[i] === i` 即係第i格已經鎖定。呢個模型**必然可解**（任何打亂咗嘅排列，一定可以逐步交換砌返晒），所以唔似番舊版卡牌配對咁需要特登驗證死局／防死鎖邏輯。

## 廣告（AdMob，framework已經接好）

跟你提供嘅參考影片，每關過關會嘗試彈一個插頁廣告（`src/services/ads.js`，用 `@capacitor-community/admob`）。**呢個喺網頁版/呢個雲端環境入面係冇作用嘅**（Capacitor偵測到唔係native app就自動跳過，唔會報錯），一定要砌成真app先會真正顯示廣告。上架前你要做：

1. 開返你自己個 [AdMob](https://admob.google.com/) 帳戶，開返App同對應嘅廣告單位（Interstitial）。
2. 將 `src/services/ads.js` 入面 `TEST_INTERSTITIAL_ID` 換成你自己嘅真實Ad Unit ID（而家用緊嘅係Google官方測試ID，開發階段唔好偷換成真ID去自己撳，會犯AdMob政策）。
3. 跟 [`@capacitor-community/admob`](https://github.com/capacitor-community/admob) 嘅文件，喺加咗 iOS/Android platform之後，去 `AndroidManifest.xml` 加 `APPLICATION_ID` meta-data，去 `Info.plist` 加 `GADApplicationIdentifier`（呢兩步要喺你自己部機、加咗native platform之後先做到，呢個雲端環境冇native project可以改）。

## 包裝做獨立 App 上架（iOS / Android）

⚠️ **呢個雲端環境冇Mac/Xcode，亦都冇裝Android Studio/SDK，所以實際起native app、簽名、上架呢幾步一定要喺你自己部電腦度做**（呢個係Apple同Google嘅硬性要求，唔係工具限制）。我已經幫你配好晒 `capacitor.config.json` 同 npm scripts，你跟住落去做：

### 1. 準備

- iOS：需要一部 **Mac** + 裝咗 **Xcode**（免費，App Store 攞）+ 你嘅 Apple Developer 帳戶（US$99/年，出正式app先需要）。
- Android：裝 **Android Studio**（Windows/Mac/Linux都得，免費）。
- 兩個平台你自己揀個 App ID（Bundle ID / Package name），例如 `com.yourname.jigsawsolitaire`，改喺 `capacitor.config.json` 嘅 `appId`（而家個placeholder係 `com.example.jigsawsolitaire`，一定要改，唔可以原封上架）。

### 2. 加平台

```bash
npm install
npm run build
npm run cap:add:ios       # 只可以喺Mac度跑
npm run cap:add:android   # Windows/Mac/Linux都得，需要Android Studio
```

### 3. 每次改完code之後同步

```bash
npm run cap:sync
```

### 4. 開返native project 微調同真機測試

```bash
npm run cap:open:ios       # 開 Xcode
npm run cap:open:android   # 開 Android Studio
```

喺 Xcode / Android Studio 入面：換App圖示同啟動畫面（icon/splash，可以用 `npx @capacitor/assets generate` 呢個工具由一張PNG自動生成晒全部尺寸）、揀你嘅簽名憑證、試跑落真機或模擬器。

### 5. 上架

- **iOS**：喺 Xcode 用 Archive → 上載去 App Store Connect，填app資料、screenshots，送審（一般1-3日）。
- **Android**：喺 Android Studio 用 Build → Generate Signed Bundle (.aab)，上載去 Google Play Console，填app資料，送審（一般數小時到1日）。

兩邊都會要求你提供私隱政策連結、app screenshots、內容分級問卷 —— 呢啲同code無關，係上架前嘅行政步驟，我做唔到但可以幫你手寫私隱政策草稿，你講聲就得。

## 介面改版（2026-08-28）

### 設計立場：相框與裱褙
6 套主題相色調差異極大（粉紅花卉 / 藍金抽象 / 橘紅熊貓…），舊版用珊瑚橘＋鵝黃漸層配紫藍底，跟一半的相打架。新版把介面本身去彩度，顏色全部交給照片：

- **環境光**（`.ambient`）：每關用該關照片模糊放大當背景，介面色調自動跟每一關和諧，換相不用改任何顏色。
- **裱褙板**（`.board-mat`）：棋盤裝在有內陰影的框裡，像一張被裱起來的照片，不再直接貼在背景上。
- **裱框金** `#d9a94e` 是唯一彩色，只用在進度與主要按鈕；玉綠 `#6fd3a8` 專門表示「已歸位」，語意色與點綴色分離。
- 單一深色主題（照片在深底最突出），所有顏色明確指定，不繼承宿主環境。
- 字體刻意用系統 CJK 字棧，**不引入 Google Fonts** —— 離線 app 用外部字體會首屏無字。

### 核心視覺：拼圖會「癒合」
- 未歸位的塊 `scale(0.965)` + 圓角 + 投影 → 像散落的碎片。
- 一歸位就 `scale(1)`、圓角歸零、去掉投影 → 無縫併入照片。
- 玩家看著整張圖逐格癒合，這是這款遊戲該有的爽感。

### 其他修正與新增
- **棋盤保證正方**，格子不再被拉長變形。
- **橫向（Landscape）版面**：棋盤與工具列左右並排。順帶修掉一個原有 bug —— `.screen` 在 ≥620px 時只寫 `margin: 0 auto`，在 column flex 容器裡會取消 stretch，寬度塌成內容寬；已補 `width: 100%`。
- **拖曳死區 12px**，手指微抖不再誤判成拖曳；拖曳時顯示落點高亮。
- **修正拖曳事件掛載**：原本 `onPointerMove` / `onPointerUp` 只在 `dragging` 為真時才掛，會漏掉第一個 move、指標離開棋盤時可能卡住拖曳狀態；改成永遠掛上、由 handler 自行判斷。
- **長按預覽原圖**（右上角眼睛鍵）—— 拼圖遊戲的必要功能。
- **音效與震動觸發點**（`src/services/feedback.js`）：邏輯只發事件不播放，換音效庫或加靜音設定只改這一支。連擊時音高遞增。音效檔留空，放進 `public/sfx/` 再填表即可。
- **過關結算**改為展示玩家剛完成的那張照片 —— 獎勵是「收藏到一張圖」，不是一個數字。
- 支援 `prefers-reduced-motion`，鍵盤焦點有可見樣式。

### 廣告
廣告位已全面接入，**細節見 [`ADS-FOR-IT.md`](./ADS-FOR-IT.md)**（給 IT 部同事的交接文件）。
新增 `src/components/AdSlot.jsx` 統一版位容器：高度先保留、廣告後填充，載入前後版面不跳動，也不會蓋住底部工具列。
`src/services/ads.js` 從只有插頁擴充成 橫幅 / 插頁 / 獎勵式 / 開屏 四種，並加了投放頻率上限 `AD_POLICY`。

### 新增依賴
- `@capacitor/haptics` —— 震動回饋。

## 多語言 i18n（2026-08-29）

依 `i18n-spec.md` 實作，三種語言：繁體中文（書面語）／簡體中文／English。

### 架構

刻意**不引入 react-i18next** —— 專案只有 3 種語言、46 條字串，沒有複數規則也沒有 RTL 需求，一個 context + 一個 `t()` 就夠，省掉重依賴與打包體積。

| 檔案 | 作用 |
|---|---|
| `src/locales/{zh-Hant,zh-Hans,en}.json` | 字串本體，flat key |
| `src/i18n/languages.js` | 語言清單、裝置語言偵測、保底語言 |
| `src/i18n/I18nProvider.jsx` | Provider（只匯出元件） |
| `src/i18n/context.js` | `useT()` / `useI18n()` hooks |
| `src/components/SettingsScreen.jsx` | 語言選擇畫面 |

語言存在獨立的 `jigsawcard-solitaire-lang-v1`，**不與 progress 混用** —— 將來動 progress schema 不會牽連語言設定。

用法：`const t = useT(); t('game.undo')`、`t('win.levelLine', { n: 3, chapterName: '貓咪' })`

新增一條字串：三個 locale 檔都加同一個 key（缺任何一個，`t()` 會退回繁體，dev 模式並在 console 警告）。

### 三個已確認的決定

1. **章節名只顯示當前語言** —— 不再中英並列。原本「風景 Nature Landscape」的英文小字副標已移除（連同 `.chapter-tile-en` 樣式）。
2. **遊戲名只有英文 PuzzlePanda**，三種語言都一樣、不翻譯。首頁原本的「拼圖接龍 + Solitaire」雙層中文標題整組移除，`index.html` 的 `<title>` 也改成 `PuzzlePanda`。

## 移除「歸位即鎖死」，改為黏合組整體移動（2026-08-29）

### 問題

舊行為：格子一歸位就完全不能再拖，游標變成禁止符號。這是多餘的限制 —— 玩家想調整已經放好的部分卻被擋住。

### 現在的行為

**1. 沒有任何禁止。** 任何格子都可以拖，包括已歸位的。
- `swapCells` 移除了「牽涉已歸位格子就拒絕」的判斷
- `.piece.is-placed` 的 `cursor` 由 `default` 改回 `grab`
- `PuzzlePiece` 不再對已歸位的格子拆掉 `onPointerDown`
- 落點判定不再排除已歸位的格子

**2. 黏合組整體移動。** 拖動一個已歸位的格子，會把它所屬的整組（上下左右四連通的已歸位格子）一起搬走：
- 整組剛性平移，形狀不變
- 目的地原本的格子被擠出來，填回這組騰空的位置
- 只要有任何一格會被推出邊界，**整個動作取消**，落點預覽一格都不亮
- 組只有一格時，行為與一般交換完全相同
- 一次整組移動只算一步

**3. 命名修正。** `locked` 改名為 `placed`（已歸位）—— 它已經不再鎖住任何東西，留著舊名字會誤導。
`computeLocked` → `computePlaced`、`.piece.is-locked` → `.piece.is-placed`、`.piece.is-just-locked` → `.piece.is-just-placed`。
⚠️ 關卡選擇頁的 `.level-tile.is-locked` / `.chapter-tile.is-locked` 意思完全不同（未解鎖的關卡），**沒有改動**。

### ⚠️ 一個要知道的後果

「已歸位」的定義就是「在自己正確的位置上」，所以**把一整組已歸位的塊移走，必然會讓它們變成不正確**，該組也隨即解散。這個功能給的是自由（想重新擺就重新擺），不是效率。組越大也越容易撞到邊界動不了。

要收回這個行為，把 `GameScreen.jsx` 裡這一行的三元運算改成永遠走 `swapCells` 即可：
```js
const newBoard = group.size > 0 ? moveGroup(...) : swapCells(...);
```

### 驗證

引擎單元測試（`src/game/engine.js`）：
- 已歸位的格子可以被拖走／拖回；兩個已歸位的格子可以互換
- 四連通組判定正確；整組平移形狀不變；沒有格子遺失或重複
- 出界時整組不動；單格組等同一般交換；未歸位格子不成組
- 5×5 隨機盤仍然可解

瀏覽器實測：整組兩片位移量完全相同（`translate(0px, 94.5px)`）、落點預覽同時高亮兩格、出界時零高亮且步數不增加、放下後整組平移且 16 片無重複。

## 核心機制修正：接合改為「相對」而非「絕對」（2026-08-29）

### 我理解錯了需求

Alice 反映：明明有幾處拼圖的內容已經接得上（樹幹、溪流連續），但畫面上它們仍然是一格一格分開的，「搞到我唔確定自己係咩齊啱」。

原因是我把「砌啱」實作成**絕對正確**（`cells[i] === i`，即這塊剛好坐在它原本那一格）。但真實拼圖不是這樣玩的 —— **兩塊接得上就應該黐住，跟它們現在放在桌上哪個位置無關**。你可以在任何地方先砌起一嚿，再整嚿搬去正確位置。

這同時解釋了我之前自己指出的矛盾：「整組移動必然令它們變成不正確」。改用相對接合之後這個矛盾消失 —— **整嚿平移時內部接合完全保留**，因為接合只看相對關係。

### 新的接合模型

兩格「接合」的條件：它們在**棋盤上**相鄰，而且手上那兩塊在**原圖上**也是同一種相鄰關係。

```js
bondedRight(cells, size, i)  // cells[i+1] === cells[i] + 1，且兩者都不跨行
bondedDown(cells, size, i)   // cells[i+size] === cells[i] + size
```

跨行保護很重要：原圖最右一列的那塊，不可以跟「下一行最左」那塊接合，否則會出現繞行的假接合。

- **cluster** = 接合關係下的連通分量
- **拖曳任何一格 = 整個 cluster 一起搬**（`connectedCluster` 取代舊的 `connectedPlacedGroup`）
- **進度 = 已接合邊數 / 總邊數**（`2 × N × (N−1)`）。全部接合等價於全部歸位，所以 100% 就是過關
- **回饋（Nice!／閃光／音效）改為「有沒有新接合」觸發**，不再等絕對歸位 —— 在任何位置砌起一嚿都即刻有反應

### 渲染：接合了的邊不畫線

每塊都填滿自己那一格（不再用 `scale(0.965)` 縮細製造縫隙）。縫隙改為**只在未接合的邊畫線**：

| 狀態 | 表現 |
|---|---|
| 未接合的邊 | 深色 1px 內線 + 頂邊淡高光（像一塊有厚度的碎片） |
| 已接合的邊 | **完全不畫** → 兩塊無縫黏成一片 |
| 整嚿已在絕對正確位置 | 外框改用玉綠 2px |

所以畫面同時回答兩件事：**「砌啱未」**（有沒有黐埋）與**「擺對位未」**（框是不是綠色）。

一個 cluster 一係全部絕對歸位、一係全部不歸位，不會一半一半 —— 若 `cells[i]===i` 且 i 與 i+1 接合，則 `cells[i+1]=i+1`，如此類推。所以綠框必然包住整嚿，不會出現半綠半黑。

### 驗證

引擎單元測試 13/13：

- 位置全錯但互相接得上 → 正確識別成一嚿（`冇一格絕對歸位` + `接合成一嚿`）
- 整嚿平移後仍然是一嚿，接合數不減少
- 搬到正確位置後整嚿變成絕對歸位
- cluster 不會一半歸位一半不歸位
- 跨行假接合被擋住
- 完成盤 = 全部邊接合 = `isSolved`
- 6×6 隨機盤仍然可解

瀏覽器實測（第 1 關 4×4）：

1. 把第 0、1 塊搬到第 5、6 格 —— **兩塊都不在自己正確位置**（絕對歸位數 0），但**進度變成 1/24**、出現「Nice!」，第 5 格右邊與第 6 格左邊都沒有線 → 無縫黏合，外框深色
2. 拖第 5 格 → 兩格一起跟手（`is-group-dragging` 同時出現在 5、6）
3. 整嚿放到第 0 格 → 兩塊同時變成絕對歸位，外框由深色轉玉綠
4. 量度接合處實際間距 = **0px**，沒有次像素縫隙
